# 分片上传（当前版本不合并）

本版提供后端分片接收、幂等重试、持久化会话、完成状态和过期清理，不提供合并、init、abort 接口。`mergeFlag=1` 只表示分片全部就位，不会创建可下载的完整文件记录。网页已接入分片编排；不超过 2 GiB 的文件走直传，大于 2 GiB 的文件走分片。文本预览保留 100 MiB 的有界读取限制。

## 会话来源

扩展现有 `POST /api/v1/files/quick-check`，兼容原请求结构，续传时可额外传入 `uploadId`：

```json
{
  "fileHash": "完整文件的32位MD5，不加盐",
  "fileSize": 3221225472,
  "fileName": "large.pdf",
  "parentFolderId": null
}
```

仍支持旧客户端的 64 位 SHA-256。只有 MD5 未命中且文件大于 2 GiB 时，创建分片会话；2 GiB 至 3 GiB 之间也走分片。文件名和父目录沿用既有校验。小文件未命中时不会生成会话。这里采用二进制单位：1 GiB = 1073741824 字节。

秒传命中时创建用户文件记录并返回 `exist=true` 和 `fileId`，不建立会话，不传输分片。未命中的大文件返回如下 `data`，外层仍为既有 `Result`：

```json
{
  "exist": false,
  "fileId": null,
  "uploadId": "upload-后端生成的UUID",
  "chunkSize": 8388608,
  "totalParts": 384
}
```

前端保存 uploadId 及文件元数据，刷新后继续使用同一会话。quick-check 未命中时，没有 uploadId 会创建新会话；携带 uploadId 会验证并恢复原会话。分片序号从 1 开始，非末片必须恰好为 chunkSize，末片必须为文件剩余字节。请求的整个文件 MD5、名称、总字节数必须与会话一致，node_type 为 `FILE`（忽略大小写）。

新直传文件在一次流式读取中计算 SHA-256 和不加盐 MD5，并保存 MD5 供秒传查询。已有物理文件的 MD5 列允许为空，不自动读取历史文件补算；历史文件只有在再次直传时才会补全 MD5。当前版本分片不会生成物理文件，因此不会成为新的秒传来源。

## 网页上传与续传

网页在 Web Worker 中按 8 MiB 分段计算完整 MD5，避免一次性载入超大文件。预检查命中后直接展示秒传成功，不切分传输分片。未命中后按 2 GiB 边界选择直传或分片，分片请求最多并发三个，网络及服务端暂时错误最多额外重试两次。

上传会话按用户、目标目录、文件名、文件总大小和 MD5 保存到浏览器本地存储。刷新后重新选择相同文件可续传，通过 [List-Parts](List-Parts.md) 分页查询服务端已完成列表；未命中秒传时仅上传缺失片，不再重传第一片探测进度。本地记录不作为服务端完成状态依据。会话过期会清除旧记录并重新预检查，越权和认证失败清除当前续传记录并终止。浏览器禁止本地存储时仍可上传，但刷新续传不可用。

全部分片就位后显示“分片已到齐，待合并”，不增加可下载文件记录。当前迭代不调用合并接口，也不将该状态计为完整文件上传成功。

## 接收分片

`POST /api/v1/files/file/chunk-upload`，`multipart/form-data`：

| 参数 | 含义 |
| --- | --- |
| name | 原始文件名，与会话一致 |
| node_type | FILE |
| size_bytes | 完整文件总字节数，long |
| uploadId | quick-check 返回的会话 ID |
| partNumber | 从 1 开始的分片序号 |
| chunk | 当前分片文件 |
| fileMd5 | 完整文件的 32 位 MD5 |

需要现有 HttpOnly 认证 Cookie 和 `X-XSRF-TOKEN`，不改变 CSRF 流程。HTTP 成功状态为 `200 OK`（200 的标准名称不是 Create）。响应：

```json
{
  "code": 200,
  "msg": "分片上传成功",
  "data": {
    "uploadId": "upload-后端生成的UUID",
    "partNumber": 5,
    "mergeFlag": 0,
    "finishedPartList": [1, 2, 3, 4, 5]
  }
}
```

已完成列表升序返回。允许乱序提交，相同 uploadId + partNumber 的有效重试直接返回成功，不再次读取请求数据或写盘。已保存分片以服务端首次完整接收的数据为准，本版不验证完整文件 MD5。

| HTTP 状态 | code | 含义 |
| --- | --- | --- |
| 401 | 401 | 用户身份校验失败 |
| 400 | 40001 | 会话不存在、非法、过期或元数据不匹配 |
| 400 | 40002 | 序号小于 1 或超过总片数 |
| 400 | 40003 | 总大小或分片长度不合法 |
| 403 | 40301 | 会话属于其他用户 |
| 413 | 41301 | 分片大小超限 |
| 500 | 50001 | 分片磁盘写入失败 |
| 400 | 400 | 表单字段缺失或类型错误 |
| 403 | 403 | 登录有效但 CSRF 校验失败 |

业务失败返回 `{ "code": 数字, "msg": "错误说明", "data": null }`。认证依赖数据库或 Redis 故障仍返回 503，以区别于无效登录。

## 存储和清理

会话存入 `chunk_upload_session` 表，分片存入 `${FILE_STORAGE_ROOT}/chunks/<uploadId>/<partNumber>.part`。完整落盘后在 `chunk_upload_part` 表登记元数据，已完成列表从数据库读取。数据库行锁串行化同一会话的接收与清理，跨实例部署需要共同数据库和共同分片文件系统。临时文件写入完成后原子移动发布，部分写入不计入已完成列表。

会话从创建时间起 24 小时后过期，不因重试延长。默认每小时清理一次，可通过 `app.storage.chunk-cleanup-delay-ms` 调整间隔。完成和未完成会话均被清理，因为本版没有合并消费这些分片。清理失败保留会话，下次重试。

## 验证

后端：`mvn test`。测试覆盖乱序接收、末片不足粒度、重复请求不读流、服务重建后续传、数据库锁并发重试、归属校验、参数异常、真实流长度限制、写入失败重试、过期回收、MD5 秒传与会话初始化，以及认证和 CSRF 回归。

前端：`npm test`、`npm run build`、`npm run test:e2e`。单元测试覆盖 MD5 块边界、秒传无二进制传输、直传分流、末片、并发限制、失败重试、服务端进度恢复及用户隔离。浏览器测试验证真实 Worker 指纹计算与秒传展示；3 GiB 以上真实文件的端到端带宽压力测试需另行执行。
