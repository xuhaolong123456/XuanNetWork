# 同名冲突规则

## 需求
用户创建或重命名文件/文件夹时，同一目录下不允许同名记录。冲突分两种处理方式：**自动改名**（创建/转移/复制）与**显式报错**（重命名）。权限、父目录存在性、重名处理都由后端负责；前端校验只用于及时提示。

## 场景与规则

### 场景一：自动改名（新建文件夹、文件转移、文件复制）
- 规则：保留扩展名，文件名后追加**全角**括号编号，例如 `文件（1）.pdf`、`旅行（1）`。
- 扩展名定义：文件名最后一个 `.` 之后的部分；无 `.` 视为无扩展名。例：`archive.tar.gz` → 扩展名 `.gz`，编号为 `archive.tar（1）.gz`。
- 编号从 1 起递增，直到找到不冲突的名字。
- 复用现有目录重名方法；若不满足"保留扩展名"，新增统一方法 `handleDuplicateFilename()`。

### 场景二：重命名（文件/文件夹）
- 不自动加编号。
- 新名 == 旧名（未变更）：直接成功（200），不视为冲突。
- 新名 != 旧名，且同目录已有同名记录：返回 409，前端 toast 报错。
- 前端做即时校验（及时提示），后端做最终裁决（兜底）。

## API 约定

| 接口 | 行为 | 结果 |
| --- | --- | --- |
| POST /api/v1/files/directories | 新建文件夹 | 201，自动改名，返回实际 name |
| PATCH /api/v1/files/directories/{id} | 重命名 | 200 成功 / 409 冲突，不自动改名 |
| （后续）文件转移 / 文件复制 | 接口待定义 | 自动改名，复用 handleDuplicateFilename |

> 本次范围：新建文件夹 + 重命名的冲突校验。文件转移/复制不在本次，接口后续定义。

## 错误约定

| 情况 | HTTP | 错误码 |
| --- | --- | --- |
| 名称为空、过长、含非法字符 | 400 | INVALID_PARAM（前端 @Valid）或 INVALID_NAME（后端） |
| 重命名同目录同名冲突 | 409 | NAME_CONFLICT |
| 父目录不存在或不属于当前用户 | 404 | FILE_NOT_FOUND |
| 未登录 | 401 | UNAUTHORIZED |

## 验收标准
1. 根目录与子目录创建重名文件夹，自动生成 `名字（1）`、`名字（2）`（全角括号），响应返回实际 name。
2. 文件自动改名保留扩展名：`报告.pdf` → `报告（1）.pdf`；无扩展名 `README` → `README（1）`；多扩展名 `archive.tar.gz` → `archive.tar（1）.gz`。
3. 重命名遇到同目录同名 → 409 NAME_CONFLICT，前端 toast 报错，不改名。
4. 重命名为原名字 → 200 成功，无变化。
5. 空名、非法名、过长名 → 400，与现有创建/重命名一致。
6. 用不存在的父目录或其他用户目录 → 404，不能创建/重命名。
7. 并发创建同名不产生重复记录（沿用现有悲观锁）。
