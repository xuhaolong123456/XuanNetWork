# List-Parts 查询已上传分片

`GET /api/v1/files/file/chunk-upload` 用于只读查询续传进度。沿用登录 Cookie，前端携带既有 `X-XSRF-TOKEN`；GET 本身不强制签发新的 CSRF 令牌。响应禁用缓存。

| 查询参数 | 默认值 | 约束 |
| --- | --- | --- |
| identifier | 必填 | 后端签发的 uploadId |
| maxParts | 100 | 1～1000 |
| partNumberMarker | 0 | 非负整数；只返回编号大于游标的分片 |

成功 HTTP 200：

```json
{
  "code": 200,
  "msg": "success",
  "data": {
    "identifier": "upload-后端签发的UUID",
    "totalParts": 384,
    "uploadedChunks": [
      { "partNumber": 1, "size": 8388608, "etag": "" },
      { "partNumber": 2, "size": 8388608, "etag": "" }
    ],
    "truncated": false,
    "nextPartNumberMarker": 0
  }
}
```

按分片编号升序返回。只查询 `maxParts + 1` 条，用额外一条判断还有没有下一页，不加载全量分片，也不计算全表数量。`truncated=true` 时，下一页游标是本页最后一条编号；没有下一页时游标为 0。空会话、超出已完成范围的游标均返回空数组和 `truncated=false`。ETag 当前预留为空字符串，不计算分片 MD5。

失败返回 `{ "code": 数字, "msg": "说明", "data": null }`：

| HTTP 状态 | code | msg |
| --- | --- | --- |
| 401 | 401 | 用户未登录，请重新登录 |
| 400 | 40001 | 分片会话不存在或者已经过期 |
| 403 | 40301 | 无权限访问该分片会话 |
| 503 | 503 | 服务暂时不可用 |
| 400 | 400 | 查询参数格式或范围错误 |

数据库、事务连接及认证 Redis 依赖故障返回 503，客户端保留续传记录并稍后重试。

## 只读约束与元数据

查询服务使用 `@Transactional(readOnly=true)`，先查会话归属和到期时间，再通过 `chunk_upload_part(upload_id, part_number)` 索引查询分片元数据。不获取会话写锁，不保存任何实体，不刷新 24 小时有效期，不访问分片目录。

POST 分片上传原子发布完整 `.part` 文件后，才登记该片的编号与实际大小。元数据登记与会话锁属于同一数据库事务。磁盘写入失败不会登记；元数据登记失败留下的完整文件，可在 POST 重试时检查长度并补录，不需要再次写盘。清理任务删除过期会话时同时删除分片元数据。

升级前仅存在于磁盘的分片不会被 GET 自动补录；前端会将其视为待上传，POST 重试可以补录而不重复写盘。部署需创建 `chunk_upload_part` 表，当前项目的 Hibernate `ddl-auto=update` 会自动创建；关闭自动建表的环境需自行执行数据库迁移。

## 前端续传

浏览器备忘录保存会话 ID、文件 MD5、大小、名称和目标目录，按当前用户隔离。刷新后重新选择同一文件，分页拉取 List-Parts 全部结果，只上传缺失片。不会再用 POST 重传第一片获取进度，也不信任本地的已完成编号。

401、40301 清除当前续传记录并终止，401 由页面现有流程跳转登录。40001 清除旧记录并重新 quick-check，命中秒传则创建文件记录，否则创建新会话。成功恢复时仍做秒传预检查，确保已经存在的完整文件不触发分片传输。503 或网络故障保留记录，停止当前尝试。分页游标停滞、倒退或异常会终止查询，避免无限请求。

本接口不实现合并、取消上传或分片 MD5 校验。

验证命令：后端 `mvn test`；前端 `npm test`、`npm run build`。
