# 本地开发与云端服务器的区别

## 1. 本地开发环境

本地开发时，浏览器、前端、后端通常运行在同一台开发电脑：

```text
浏览器
  └─ http://localhost:5173
       └─ Vite 前端开发服务器
            └─ 将 /api 请求代理到 http://127.0.0.1:9090
                 └─ Spring Boot 后端
                      ├─ MySQL：127.0.0.1:3306
                      ├─ Redis：127.0.0.1:6379
                      └─ SMTP 邮件服务：外部服务
```

项目的 `start-dev.bat` 用于本地启动：前端监听 `127.0.0.1:5173`，并将 `/api` 代理到 `127.0.0.1:9090`。由于浏览器只在本机使用，监听回环地址即可，不会暴露到局域网或公网。

## 2. 云端服务器环境

云端部署时，用户的浏览器运行在用户自己的电脑或手机上，前后端进程运行在云服务器上：

```text
用户浏览器
  └─ http://服务器公网地址:5173
       └─ 云服务器上的前端服务
            └─ 将 /api 请求代理到服务器可达的后端地址:9090
                 └─ Spring Boot 后端
                      ├─ MySQL：服务器内网地址或托管数据库地址
                      ├─ Redis：服务器内网地址或托管 Redis 地址
                      └─ SMTP 邮件服务：外部服务
```

如果前后端部署在同一台云服务器，前端代理目标可以是 `http://127.0.0.1:9090`。如果后端在另一台机器或容器中，目标必须填写前端进程所在环境能够访问到的后端地址，例如内网 IP、服务名或内部域名。

## 3. `localhost` 的含义

`localhost` 永远表示“当前发起连接的进程所在的机器或网络命名空间”，不表示某个固定服务器：

- 开发电脑上的浏览器访问 `localhost:5173`，连接的是开发电脑。
- 云服务器上的 Vite 代理访问 `localhost:9090`，连接的是云服务器自身的 9090 端口。
- 用户浏览器访问 `localhost:9090`，连接的是用户自己的设备，通常不是云服务器。
- 若服务运行在容器中，容器内的 `localhost` 通常只表示该容器本身。

因此，前端代码使用同源的 `/api/...` 地址时，浏览器先请求前端站点；再由 Vite、Nginx 或其他反向代理将 API 转发给后端。不要把浏览器侧 API 地址写成访问者的 `localhost`。

## 4. 端口和监听地址

| 端口 | 项目用途 | 本地开发 | 云端部署 |
| --- | --- | --- | --- |
| `5173` | Vite 前端开发服务 | 默认仅监听 `127.0.0.1` | 临时公网联调需监听 `0.0.0.0`，并在云防火墙及系统防火墙放行；生产建议由 Nginx/HTTPS 入口提供网站 |
| `9090` | Spring Boot API | 本地后端端口 | 通常只允许本机或内网访问，不建议直接向公网开放 |
| `3306` | MySQL | 本机或开发数据库 | 建议只允许后端主机/内网访问 |
| `6379` | Redis | 本机或开发 Redis | 建议只允许后端主机/内网访问 |

`0.0.0.0` 是服务端的监听地址，表示监听所有网卡；它不是用户访问时要输入的目标地址。用户访问应使用服务器公网 IP、域名或负载均衡地址。

## 5. 前端代理配置

`frontend/vite.config.js` 使用以下环境变量：

- `HOST`：Vite 监听地址。本地默认 `127.0.0.1`；远程联调时可设为 `0.0.0.0`。
- `API_TARGET`：Vite 收到 `/api` 请求后转发的后端地址。本地默认 `http://127.0.0.1:9090`；云端应设为前端进程能够访问的后端地址。

云端临时联调示例（前后端同机）：

```bash
HOST=0.0.0.0 API_TARGET=http://127.0.0.1:9090 npm run dev -- --host 0.0.0.0
```

若后端在另一台机器，应把 `API_TARGET` 改成后端内网地址，例如 `http://10.0.0.20:9090`。改变环境变量后必须重启 Vite，因为配置在进程启动时读取。

Vite 开发服务用于开发和临时联调，不建议直接充当正式生产 Web 服务。生产部署通常先执行 `npm run build`，将 `frontend/dist/` 交给 Nginx 等静态 Web 服务器，再由同一个站点入口将 `/api/` 反向代理至后端。让网页和 API 保持同源，便于继续使用认证 Cookie 和 CSRF 校验。

## 6. 后端配置与运行

本地配置位于被 Git 忽略的 `backend/src/main/resources/application-dev.yml`，包含本机 MySQL、Redis 等开发连接参数。不要将本地文件原样上传到服务器，也不要把生产密码、JWT 密钥、邮件凭据写入仓库或镜像。

云端应使用环境变量或专用配置管理系统注入生产值，包括：

- 数据库 URL、用户名和密码
- Redis 地址、端口和密码
- `AUTH_TOKEN_SECRET`（使用独立的高强度随机密钥）
- `REDIS_KEY_SECRET`
- 邮件服务凭据及发件人
- `AUTH_COOKIE_SECURE=true`（HTTPS 部署时）
- 文件存储根目录 `FILE_STORAGE_ROOT`

后端可打包为 Spring Boot 可执行 JAR。服务器上应由 systemd、容器平台或其他进程管理器启动和重启；替换 JAR 前备份旧包，重启后检查服务状态、日志和 API 响应。不要只依赖 SSH 会话中的临时前台进程运行生产服务。

## 7. 故障排查提示

- 页面打不开：确认前端服务正在运行、监听地址允许远端连接，且云安全组与系统防火墙放行网站端口。
- JS/CSS 返回 404：检查静态文件是否使用最新构建产物，部署的 HTML 与 `dist/assets` 是否来自同一次构建，以及前端站点的根路径配置。
- `/api` 超时或返回 500：检查前端代理的 `API_TARGET`，再按请求时间检查后端日志；同时确认后端到 MySQL 和 Redis 的连接。
- 只有 `/me` 超时：检查请求是否进入后端、认证 Cookie 是否发送，以及后端 JWT 过滤器访问 Redis 和数据库时是否报错。
- 浏览器请求挂起不会因为 Vue 单线程而自动耗时两分钟。`fetch` 等网络调用是异步的；长等待通常来自代理、网络或后端依赖没有及时响应。前端超时只能结束浏览器等待，不能代替修复服务端故障。

## 8. 当前项目状态记录

- 后端监听端口默认是 `9090`。
- 前端 Vite 开发端口是 `5173`。
- 本地启动脚本将 `/api` 代理到本机 `127.0.0.1:9090`。
- 前端已支持通过 `HOST` 与 `API_TARGET` 调整 Vite 监听和代理目标。
- 普通前端 API 请求设有 15 秒等待上限；文件上传、下载及分片请求最长等待 10 分钟。
- 已在前端路由守卫中合并并发的会话检查，减少重复 `/api/v1/auth/me` 请求。
- 云端出现 HTTP 500 的最终原因仍应以对应时间的后端日志为准；应确认新前端和后端包已实际部署并重启后再复测。
