# 文件夹树

## 接口

`GET /api/v1/files/file/tree`

接口从登录态取得用户 ID，只查询该用户未删除的文件夹记录。一次查询得到 `id`、`parentId`、`name`，后端在内存中按 `parentId` 分组；数据库中的根目录 `parent_id` 为空，对外统一使用 `parentId: 0`。每个节点另含 `children` 数组。

存在文件夹时返回 HTTP 200 和 `Result` 包装的树。例如：

```json
{
  "success": true,
  "code": "OK",
  "data": [
    { "id": 1, "parentId": 0, "name": "资料", "children": [
      { "id": 2, "parentId": 1, "name": "图片", "children": [] }
    ] }
  ]
}
```

当前用户没有未删除的文件夹记录时返回 HTTP 204，无响应体。未登录或认证无效时按接口约定返回 HTTP 404，且不暴露其他用户的数据。目录记录存在断链或循环时返回 409，避免静默遗漏目录。

## 页面

左侧回收站下方的“文件夹树”按钮跳转 `/drive/tree` 独立页面。页面把文件夹显示为节点，以连线表示真实的父子关系，并增加“我的文件”虚拟根节点连接顶层目录。节点布局呈拓扑图，支持拖动、滚轮或按钮缩放、名称查找；点击节点可查看路径并进入对应目录。接口返回 204 时显示“无文件”。页面刷新时重新读取最新目录记录。

## 验证

运行 `mvn test`、`npm test`、`npm run build`、`npm run test:e2e`。回归覆盖用户归属、软删除、根节点映射、空树和侧栏交互。
