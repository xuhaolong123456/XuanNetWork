# Redis 分布式邮箱验证码设计与学习记录

## 1. 设计目标

将邮箱验证码从单机 JVM 内存迁移到 Redis，实现以下能力：

- 多个 Spring Boot 实例共享验证码状态。
- 验证码自动过期。
- 防止同一验证码被并发重复注册。
- 防止同一邮箱频繁发信。
- 记录验证码安全事件，但不记录敏感明文数据。
- Redis 故障时明确拒绝验证码相关请求，不降级到本地内存。

## 2. 为什么不继续使用内存

单机模式下，验证码保存在同一个 Java 进程内存中，发送和注册请求都落到同一服务时可以正常工作。

分布式部署时，负载均衡可能把请求分发到不同实例：

```text
发送验证码请求 → 服务 A → A 的内存保存验证码
注册请求       → 服务 B → B 的内存中没有验证码
```

服务 A 与服务 B 的 JVM 内存互相隔离，因此验证码会校验失败。Redis 放在应用实例之外，所有实例都访问同一份数据：

```text
发送验证码请求 → 服务 A → Redis
注册请求       → 服务 B → Redis
```

## 3. 已确认的业务规则

| 规则 | 已确认方案 |
|---|---|
| 验证码有效期 | 60 秒 |
| 前端展示 | 60 秒倒计时 |
| 同邮箱重发冷却 | 60 秒 |
| 重新发送 | 覆盖旧验证码、重置错误次数和倒计时 |
| 最大错误次数 | 3 次；第三次错误后验证码失效 |
| 错误提示 | 显示“验证码错误，还可尝试 N 次” |
| 昵称重复 | 可修改昵称后使用原验证码重试 |
| 邮箱已注册 | 不发邮件，返回 `EMAIL_EXISTS`，提示直接登录 |
| 数据库临时异常 | 释放注册使用锁，允许在剩余 TTL 内重试 |
| 注册成功 | 删除验证码和注册使用锁 |
| 注册使用锁 | 30 秒 TTL |
| 发送临时锁 | 30 秒 TTL，按邮箱隔离 |
| 同邮箱每日发送上限 | 10 次，按北京时间 00:00 重置 |
| IP 限流 | 10 次/分钟，当前采用固定窗口 |
| Redis 不可用 | 应用启动失败；运行中接口返回 `503` |
| Redis 单次命令超时 | 2 秒 |
| Redis 启动探活 | 2 秒、4 秒、6 秒，三次均失败则启动失败 |
| 邮件发送方式 | 同步发送 |
| 邮件与 Redis 顺序 | SMTP 成功后写 Redis；Redis 写失败返回 `503` |
| 审计日志 | 写应用日志文件，按天滚动，保留 7 天 |

## 5. Redis Key 安全设计

邮箱不能直接作为 Redis Key 的一部分，因为 Key 可能出现在监控、备份、命令历史或排障截图中。

不能使用 BCrypt 生成 Redis Key：BCrypt 每次都会生成不同结果，无法让不同请求、不同服务实例定位同一个 Key。

使用确定性的 HMAC-SHA-256：

```text
emailKey = HMAC-SHA-256(REDIS_KEY_SECRET, normalize(email))
```

其中 `normalize(email)` 表示去除首尾空格并转为小写。相同邮箱在所有实例中得到相同 Key，但没有服务端密钥时难以从 Key 反推邮箱。

验证码也不明文保存：

```text
codeDigest = HMAC-SHA-256(REDIS_KEY_SECRET, normalize(email) + ":" + code)
```

Redis 保存 `codeDigest`，校验时对用户输入再次计算 HMAC 并比较。

## 6. Redis Key 规划

```text
verify:code:{emailKey}       → 验证码 HMAC 摘要，TTL 60 秒
verify:cooldown:{emailKey}   → 邮箱重发冷却，TTL 60 秒
verify:daily:{emailKey}      → 当日发送次数，TTL 到下个北京时间零点
verify:fail:{emailKey}       → 验证码错误次数，TTL 60 秒
verify:register-lock:{emailKey} → 注册使用锁，TTL 30 秒
verify:send-lock:{emailKey} → 邮件发送临时锁，TTL 30 秒
verify:ip:{clientIp}         → IP 固定窗口计数，TTL 60 秒
```

## 7. 发送验证码流程

```text
前端校验邮箱格式
    ↓
后端查询邮箱是否已注册
    ↓
已注册：返回 400 + EMAIL_EXISTS，不发送邮件
    ↓
Redis 检查 IP 固定窗口（10 次/分钟）
    ↓
Redis 检查邮箱冷却与当日次数
    ↓
SET NX EX 获取 send-lock（30 秒）
    ↓
同步调用 QQ SMTP 发送邮件
    ↓
SMTP 成功：写验证码摘要、冷却键、每日计数和错误计数
    ↓
写 Redis 成功：返回成功
写 Redis 失败：返回 503，日志记录严重事件
```

发送锁按邮箱隔离：不同邮箱不会互相影响；同一个邮箱即使来自不同 IP，也只能有一个请求进入 SMTP 流程，避免同时发送多个互相覆盖的验证码。

## 8. 注册校验流程

```text
前端校验验证码为 6 位数字
    ↓
后端 Lua 脚本原子执行：验证码匹配 + 检查错误次数 + 获取 register-lock
    ↓
失败：返回错误、剩余尝试次数或过期提示
    ↓
成功：进入数据库注册
    ↓
昵称重复：释放 register-lock，保留验证码，允许修改昵称后重试
邮箱重复：删除验证码和 register-lock，返回 EMAIL_EXISTS
数据库异常：释放 register-lock，保留验证码，在剩余 TTL 内允许重试
注册成功：删除验证码、错误次数和 register-lock
```

Lua 脚本用于把多条 Redis 操作合并成原子操作，避免两个服务实例同时使用同一验证码完成注册。

## 9. HTTP 状态码和前端提示

| 状态码 | 业务码示例 | 前端提示 |
|---:|---|---|
| 400 | `EMAIL_EXISTS` | 该邮箱已注册，请直接登录 |
| 400 | `INVALID_EMAIL_CODE` | 验证码错误，还可尝试 N 次 |
| 400 | `CODE_EXPIRED` | 验证码已过期，请重新获取 |
| 429 | `EMAIL_COOLDOWN` | 请在 XX 秒后重新获取 |
| 429 | `DAILY_LIMITED` | 该邮箱今日验证码发送次数已达上限 |
| 429 | `SEND_IN_PROGRESS` | 验证码已经发送，请稍后 |
| 429 | `IP_RATE_LIMITED` | 当前请求过于频繁，请稍后重试 |
| 503 | `REDIS_UNAVAILABLE` | 验证码服务暂不可用，请稍后重试 |
| 503 | `MAIL_SEND_FAILED` | 邮件服务发送失败，请稍后重试 |

前端还需要区分：

- 客户端校验失败：邮箱格式错误、验证码不是 6 位数字，不发请求。
- 客户端网络失败：网络断开、请求超时、无法访问后端，提示检查网络。
- 服务端失败：根据 HTTP 状态码和业务码显示可理解提示，不展示密码、连接串或 SMTP 细节。

## 10. 前端验证码输入体验

- 使用 6 个独立数字输入框。
- 输入一位后自动跳到下一格。
- 支持粘贴完整 6 位验证码后自动填满。
- 注册前验证必须为 6 位数字。
- 后端返回验证码过期时提示重新获取，不强制清空用户当前输入。

## 11. 固定窗口限流

当前 IP 限流先使用固定窗口：

```text
KEY：verify:ip:{clientIp}
操作：INCR
TTL：60 秒
阈值：10
```

如果计数超过 10，则拒绝。固定窗口实现简单，但在两个分钟窗口交界处可能出现短时间突发，例如一分钟末尾发 10 次、下一分钟开头再发 10 次。

客户端 IP 获取规则：

```text
本地开发：使用 HTTP 连接来源 IP
生产部署：仅信任自有 Nginx / 网关写入的 X-Forwarded-For
```

不能直接信任客户端自行传来的 `X-Forwarded-For`，因为它可以被伪造。

## 12. 学习记录：令牌桶（待后续演进）

令牌桶是一种更平滑的限流算法，可以理解为：

```text
桶最多放 10 张发送券
每次发送验证码消耗 1 张券
系统按固定速率补回发送券
桶空时拒绝请求
```

如果设定“容量 10、每分钟补充 10 个令牌”，空闲一段时间后最多可以立即发送 10 次，但长期平均速率不会超过 10 次/分钟。

与固定窗口相比，令牌桶对时间边界的突发更平滑，通常使用 Lua 脚本原子更新令牌数量和上次补充时间。

当前不实现令牌桶，保留为后续学习和优化项。

## 13. 审计日志规则

记录以下事件：

- 验证码发送成功或失败。
- SMTP 失败。
- Redis 不可用或超时。
- 验证码校验成功或失败。
- 三次错误导致验证码失效。
- 邮箱冷却、每日上限和 IP 限流命中。
- 注册成功、昵称重复、邮箱重复、数据库异常。

日志禁止记录：

- 明文验证码。
- 完整邮箱。
- Redis Key。
- Redis 密码。
- HMAC 密钥。
- QQ 邮箱授权码。

邮箱仅以脱敏形式记录，例如 `u***@example.com`。日志按天滚动，保留 7 天。
